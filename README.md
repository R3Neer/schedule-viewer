# Schedule Viewer

[![Deploy GitHub Pages](https://github.com/R3Neer/schedule-viewer/actions/workflows/pages.yml/badge.svg)](https://github.com/R3Neer/schedule-viewer/actions/workflows/pages.yml)

A local-first, offline image viewer for calendars, rotating displays and time-based information.

<p align="center">
  <a href="https://r3neer.github.io/schedule-viewer/"><strong>Open the live demo →</strong></a>
</p>

![Schedule Viewer on desktop and iPhone](docs/media/hero.png)

Schedule Viewer chooses an image from the current period, calendar state and screen orientation. Its public demo contains only neutral, generated planner artwork. Your own configuration and images stay in your browser: there is no account, server-side storage or analytics layer.

## What it does

- **General periods.** Define any named date ranges, from a conference season to a household rota. Periods cannot overlap.
- **Real calendar rules.** Combine a weekly pattern, exact active or inactive exceptions, and named inactive intervals such as holidays or closures.
- **Simple presentation model.** Portrait can vary by day, real week or calendar month; landscape uses one stable image for the whole period.
- **Image-only and lossless.** PNG, JPEG, WebP, AVIF and animated GIF are stored with their original bytes. User SVG is intentionally rejected.
- **Local and portable.** IndexedDB stores configuration and images; a `.schedule` backup carries both to another browser.
- **Offline and installable.** The app shell and demo work through a Service Worker and can be added to an iPhone or iPad Home Screen.
- **Accessible interaction.** Grouped Apple-style settings, keyboard navigation, safe touch gestures and interruptible motion all honor Reduce Motion.

## Use it

1. Open the [live app](https://r3neer.github.io/schedule-viewer/).
2. Open the floating settings control.
3. Configure **Periodos**, **Calendario**, **Presentación** and **Imágenes**.
4. Select **Guardar cambios**, then export a `.schedule` backup before clearing browser data or moving devices.

On touch devices, portrait selects the Vertical presentation and landscape selects Horizontal. On desktop, Horizontal is the default and Space can alternate the presentation when that option is enabled.

## Data and backups

```text
neutral public demo
        ↓
 six-section settings UI
        ↓
IndexedDB configuration + original image Blobs
        ↓
 calendar-aware image renderer
```

A YAML export contains the v4 configuration only. Use **Copia de seguridad** to include local image bytes in a `.schedule` package. Imports are validated before replacing current data and report the precise path and cause of schema errors.

Version 3 image-backed configurations can migrate automatically. A legacy configuration that depends on generated timetable structures or SVG is kept isolated, never overwritten silently, and can be downloaded for recovery.

## Configuration v4

The neutral demo lives in [`config/schedule.yaml`](config/schedule.yaml). The build normalizes it to the same public v4 contract used by the browser editor:

```text
config/schedule.yaml → validated v4 model → dist/config/schedule.json
```

See [`docs/config-v4.md`](docs/config-v4.md) for the schema and calendar precedence, and [`docs/local-config.md`](docs/local-config.md) for persistence and backup details.

## Development

Requirements: Python 3.11+, Node.js 22+ and Playwright browser dependencies.

```bash
python -m pip install -r requirements.txt
npm ci --no-audit --no-fund
npx playwright install chromium webkit

python tools/validate_config.py
python tests/config-v4.test.py
npm test
python tools/build.py --out dist
npm run test:e2e
```

Serve `dist/` through HTTP; opening the HTML file directly does not provide the Service Worker environment.

Regenerate the public screenshots and visual-review matrix after UI changes:

```bash
npm run capture:readme
python tools/compose_readme_media.py
python tools/validate_showcase.py
```

The quality barrier and device matrix are documented in [`docs/qa.md`](docs/qa.md). Contributions are described in [`CONTRIBUTING.md`](CONTRIBUTING.md).

## Deployment

Every push and pull request validates v4, runs unit and browser contracts, builds the exact artifact, checks offline updates and exercises the optical Apple material under WebKit. A successful push to `main` deploys that exact `dist/` tree to GitHub Pages.

Release-isolated module paths prevent an older installed Service Worker from mixing stale JavaScript into a new release. IndexedDB configuration and image Blobs survive application updates.
