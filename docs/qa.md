# Quality assurance

GitHub Pages receives the exact `dist/` artifact only after every required check succeeds.

## Static and privacy validation

- `config/schedule.yaml` is the only source configuration.
- `tools/validate_config.py` parses, normalizes and validates schema v3.
- `tools/audit_public_tree.py` scans every tracked text file for inherited private schedule identifiers.
- The build verifies all referenced local assets and release-isolated module copies.
- Generated timetable WebP files must pass dimension, variety and contrast checks.
- Showcase source images stay outside `assets/` and therefore outside `dist/`.

## Unit contracts

The Node and Python suites cover calendar rules, ranges, view selection, content precedence, rendering, persistence, atomic IndexedDB writes, `.schedule` packages, YAML round-trips, Service Worker updates and migration behavior.

The motion model includes a long-frame contract: a delayed rendering frame must advance using real elapsed time instead of freezing a transition at an intermediate position.

## Browser coverage

The Chromium suite exercises:

- touch portrait and landscape without reloading;
- desktop primary/secondary views and keyboard toggling;
- active and inactive image menus across periods;
- settings navigation, interruption, focus, scroll restoration and Reduce Motion;
- YAML import/export and lazy editor loading;
- backup restore and local Blob persistence;
- offline launch, installed-client updates and safe reload coordination;
- repeated animation cycles without leaked layers.

A separate WebKit suite requires the optical Liquid Glass renderer to mount successfully and confirms that the material remains limited to the floating control. Its CSS fallback is tested independently.

## Visual release review

Motion reviews use phone portrait, narrow phone, landscape and desktop captures in light, dark and reduced-motion modes. Acceptance requires stable end positions, no partial stalls, no focusable hidden panels, no header jumps and no renderer rebuild on every frame.

README captures are deterministic documentation artifacts generated by `tools/capture_readme.mjs`. They use fresh browser profiles and the public-domain fixtures documented in `showcase/README.md`.
